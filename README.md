# mori. — лёгкие заметки и закладки с GitHub Gist

**Версия:** 2.0 (без Firebase). Один статический сайт для Windows и iPhone. Нужен только GitHub.

## Главное — как синхронизировать

**GitHub Pages** бесплатно показывает сайт. **GitHub Gist** хранит **зашифрованную** копию заметок. Сам GitHub Gist не является приватным: любой человек с URL может открыть Gist, но содержимое заметок в нём зашифровано.

- На устройствах заметки сохраняются локально в IndexedDB и работают офлайн после первого посещения сайта.
- При нажатии **«Синхронизировать»** mori. скачивает облачную копию, сравнивает изменения и загружает объединённые заметки. **Автоматической синхронизации нет**: перед сменой устройства и после работы на нём нажимай кнопку.
- При конфликте параллельных правок создаётся заметка «(конфликт синхронизации)», чтобы не потерять текст.
- GitHub-токен сохраняется **только в браузере каждого устройства**. Пароль шифрования не сохраняется на диск: его нужно вводить заново после перезапуска приложения/страницы, затем кнопка работает до перезагрузки.

## 1. Запусти сайт на GitHub Pages

1. Распакуй архив.
2. На https://github.com/new создай **публичный** репозиторий `mori-notes`.
3. Загрузить через **Add file → Upload files** содержимое папки `mori-notes`: `index.html`, `app.js`, `styles.css`, `sync.js`, `db.js`, `markdown.js`, `sw.js`, `manifest.webmanifest`, папку `icons`, `.nojekyll` (последний опционален) и этот README.
4. Нажми **Commit changes**.
5. Зайди в **Settings → Pages → Source: Deploy from a branch → main → /(root) → Save**.
6. Открой адрес `https://ТВОЙ_НИК.github.io/mori-notes/`.

Без GitHub Pages можно тестировать локально через `python -m http.server`, открыв `http://localhost:8000`. **Не открывай `index.html` двойным кликом**: JS-модули и Service Worker могут не работать с `file://`.

## 2. Создай один GitHub-токен

1. Открой https://github.com/settings/tokens/new (или GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic)).
2. В поле Note напиши `mori sync`.
3. Expiration: выбери подходящий срок. Токен после истечения срока потребуется заменить на обоих устройствах. При использовании `No expiration` токен требует особенно бережного хранения.
4. **Поставь галочку ТОЛЬКО `gist`**. Не отмечай repo, workflow и другие разрешения.
5. Нажми **Generate token**, скопируй строку (например `ghp_...`). GitHub покажет её только один раз. Это **секрет**; никому его не отправляй, не публикуй в GitHub, не вставляй в код сайта.

> GitHub позволяет создавать классические Personal Access Tokens с доступом к gist. Fine-grained token может не иметь нужной поддержки; выбирай **Tokens (classic)**.

## 3. Первый компьютер — создаём зашифрованное облако

1. Открой свой сайт mori. и создай/сохрани тестовую заметку.
2. Нажми в шапке **«Синхронизировать»**.
3. Вставь GitHub-токен.
4. Введи **отдельный пароль шифрования длиной от 12 символов**. Это НЕ пароль GitHub, а новый пароль для защиты заметок. Запиши его в надёжном месте: **восстановить его невозможно**.
5. Нажми **«Синхронизировать»** в окне.
6. При успехе увидишь зелёную точку и надпись «Синхронизировано». Приложение автоматически создаст *Secret Gist* с зашифрованными файлами `mori-vault.json` и `mori-part-000.txt` (при большом объёме — несколько `mori-part-...`).

Не нужно вручную создавать Gist, копировать ID или писать настройки базы данных.

## 4. iPhone — подключаем те же заметки

1. Открой **Safari** и адрес своего сайта.
2. Нажми «Синхронизировать» и вставь **тот же GitHub-токен и тот же пароль шифрования**.
3. Нажми кнопку. Сайт сам найдёт зашифрованный Gist в твоём GitHub-аккаунте и скачает заметки.
4. В Safari нажми **Поделиться → На экран «Домой» → Добавить**, чтобы пользоваться сайтом почти как приложением.
5. Создай новую заметку на iPhone, **нажми «Синхронизировать»**. На ПК снова нажми кнопку: заметка появится и там.

**Важное правило:** синхронизируй перед работой на другом устройстве и после неё. Без нажатия кнопки новые заметки остаются только на текущем устройстве.

## 5. Что умеет mori.

- Почти чёрный адаптивный интерфейс, карточки как в Google Keep, полноэкранный редактор с анимацией.
- Редактирование заголовка и до 240 000 символов текста в одной заметке.
- Markdown с предпросмотром и безопасно подсвеченными ссылками.
- Закладки сайтов с URL, ручной обложкой и поиском картинки через Microlink (для обложек нужен интернет, сервис узнаёт URL).
- Поиск, закрепление, цвета, перетаскивание карточек.
- Локальная IndexedDB, офлайн PWA, импорт `.md`, экспорт `.md`, импорт и экспорт резервной копии JSON.
- Ручная шифрованная синхронизация через Gist, объединение заметок с обоих устройств.

## Безопасность и ограничения — прочти

1. **Secret Gist не приватен.** Данные шифруются AES-256-GCM с ключом, полученным через PBKDF2-SHA256, 250 000 итераций, случайными salt/IV. Никто не должен видеть исходные заметки без пароля; однако сам факт наличия Gist и техническая информация видны обладателю ссылки.
2. **Токен хранится в IndexedDB в открытом виде на твоём устройстве** ради удобства. Он доступен JavaScript-коду того же сайта; не открывай неизвестные копии mori. и не устанавливай сомнительные расширения. Если устройство скомпрометировано, отзови токен в настройках GitHub. Кнопка «Забыть токен» очищает локальное значение, но **не отозвает** его на GitHub.
3. **Не теряй пароль шифрования!** Если он потерян, облачный архив не восстановить. Локальные заметки на уже используемых устройствах останутся, пока не очищены данные браузера.
4. **Граница размера:** локальная заметка до 240 000 символов; общий JSON-архив для одного Gist до 12 МБ (после шифрования разбивается на файлы меньше 400 КБ). Огромные коллекции картинок не поддерживаются — храним ссылки на обложки, не сами изображения.
5. **GitHub Gist не база данных.** При одновременном нажатии синхронизации на двух устройствах возможны гонки: синхронизируй по очереди. GitHub хранит историю ревизий Gist, но автоматического восстановления всех исторических версий в приложении нет.
6. **Локальные данные не шифруются.** IndexedDB хранит заметки обычным текстом. Если кому-то доступен твой разблокированный компьютер или браузерный профиль, он может получить их.
7. **Периодически скачивай резервную копию JSON** через меню, особенно перед крупными изменениями или очисткой браузера. Бэкапы содержат текст без шифрования — береги файл.
8. На iPhone очистка данных Safari или удаление PWA может удалить локальные заметки. Работа офлайн зависит от наличия кэша PWA и сохранённых локальных данных.
9. Бесплатность зависит от правил GitHub, разумных объёмов и API-лимитов; приложение не обещает неограниченное облачное хранилище.

## Если проблема

- **«GitHub отклонил токен»** — проверь, что создал **classic PAT** с `gist` и он не истёк.
- **«Неверный пароль»** — вводи в точности тот же пароль шифрования, что на первом устройстве. Не создавай новый, если Gist уже существует.
- **«Нет связи с GitHub»** — проверь интернет и попробуй снова, локальные заметки не исчезают.
- **После публикации сайт старый** — перезагрузи вкладку, закрой старую PWA. Service Worker обновляет статику после загрузки новой версии, иногда нужен повторный запуск.
- **Несколько архивов mori.** — приложение предупредит, вместо случайного выбора. Лишние Gist можно удалить вручную на https://gist.github.com/, предварительно сохранив резервную копию.

## Для разработчика

Только HTML/CSS/JavaScript (ES Modules), без сборки, без npm, без Firebase/Supabase. Синхронизация в `sync.js`; интерфейс в `app.js`; `db.js` — IndexedDB; `markdown.js` — безопасный минимальный рендерер; `sw.js` — офлайн-кэш. Никаких секретов в исходниках. Протокол облака: `mori-vault.json` (метаданные шифрования) + `mori-part-NNN.txt` (части base64 зашифрованных данных).
